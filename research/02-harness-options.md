# Reusable agent harnesses for HeyNimbo

Research date: **2026-10-29**; retrieval and installed-package probe timestamps are preserved in `evidence/harness-sources.json` and `evidence/harness-ai-probe-result.json`. All harness-prefixed support files referenced by basename below now live under `research/evidence/`; bulky downloaded snapshots are local-only, not vendored dependencies.
Scope: architecture choice, not implementation; public primary documentation, pinned source, fetched LICENSE files, and read-only installed-source inspection.
**Recommendation: own the desktop agent substrate, thin-compose the already-installed AI SDK 7 loop, and delegate coding through optional isolated adapters.**
Do not make Codex, Hermes, Pi, OpenCode, or Vercel's new harness abstraction the authority for desktop capabilities, canonical memory, or speech/scene timing.

## 1. Decision and hard gates

- **Provider-agnostic rich desktop tools: yes without a rewrite**, most directly with existing AI SDK providers plus host-owned typed tools; Pi and OpenCode also expose genuine embedding boundaries, but bring different provider/session representations. [AI loop](https://ai-sdk.dev/docs/agents/loop-control), [Pi SDK](https://github.com/earendil-works/pi/blob/e7a0df27c09d11bf4161d3605246cbf57a129cb2/packages/coding-agent/docs/sdk.md), [OpenCode SDK](https://github.com/anomalyco/opencode/blob/87a35fa43ac51ecb89ddafdb8dad07f79e967c43/packages/sdk/README.md).
- **Delegated-engine permissions: conditional, not automatic.** Host-defined tools can enforce a broker decision before acting; built-in shell/file tools execute inside the engine's authority and are not made safe by translating their events. [Harness ownership](https://ai-sdk.dev/docs/ai-sdk-harnesses), [Codex driver](https://github.com/vercel/ai/blob/ede06e32cf5ac1d79e29bc07cd4e3839e8998a0b/packages/harness-codex/src/bridge/codex-app-server-driver.ts).
- **Hermes adoption requires Python somewhere.** Local bundling means shipping/managing a Python runtime and Hermes dependencies; connecting to a separately managed Hermes service avoids bundling, not Python execution. Current library guidance supports a prepared source checkout, not a supported wheel/sdist install. [Library](https://github.com/NousResearch/hermes-agent/blob/fcc26fbd9f1641755e49793d7ed608f3b7214c3d/website/docs/guides/python-library.md), [Python requirement](https://github.com/NousResearch/hermes-agent/blob/fcc26fbd9f1641755e49793d7ed608f3b7214c3d/pyproject.toml).
- **Own loop does not mean reimplement provider adapters.** Own admission, checkpoints, cancellation, policy, memory, skills, event envelopes, and recovery; reuse `ToolLoopAgent` or lower-level model calls for execution. [Loop customization](https://ai-sdk.dev/docs/agents/loop-control).
- Prefer a pinned direct Codex app-server adapter for optional Codex coding; evaluate `HarnessAgent` normalization only after its sandbox and permission contract passes desktop tests. Its Codex bridge deliberately turns native approvals off. [Driver](https://github.com/vercel/ai/blob/ede06e32cf5ac1d79e29bc07cd4e3839e8998a0b/packages/harness-codex/src/bridge/codex-app-server-driver.ts).
- Keep the existing speech/drawing/3D orchestrator independent: agent activity emits validated app events; it must not replace the playback clock or execute model-authored renderer code. **Architecture recommendation**, grounded in local `docs/architecture.md`.

## 3. Decision matrix

Ratings are **integration judgments for this repository**, not benchmark results; features and caveats are substantiated in the candidate sections.

| Option | Provider breadth | Rich desktop tools | Stream / steer / stop | Persistence and learning | Permission fit | Integration cost | Verdict |
|---|---|---|---|---|---|---|---|
| Own substrate + installed AI loop | Existing adapters retained | Direct typed host tools | Stream + experimental boundary steering + signal | Host supplies durable journal, memory, skills | Best place to impose broker | Medium substrate work, least migration | **Default** |
| Pi agent-core | pi-ai stack or custom stream bridge | Direct `AgentTool` | Events + steer/follow-up + abort | Core state; host owns product persistence | Preflight hook, no OS isolation | Medium; provider/message bridge | Best small alternative |
| Pi coding-agent SDK | pi-ai stack | Custom tool/resource factories | Rich session lifecycle | JSONL branches, compaction, skills; memory policy remains host choice | Strip defaults, broker tools | Medium–high; another session/resource system | Strong complete TS comparator |
| Hermes sidecar | Broad/native/local routing | Python plugin or MCP bridge | Library callbacks; RPC/API control | Most complete built-in memory + learned skills | Requires restrictive deployment; fail-open middleware caveat | High Python packaging and dual ownership | Optional generalist worker, not default core |
| Codex app-server | Responses-compatible/custom/local, not arbitrary provider parity | Experimental dynamic client tools or MCP | Rich native protocol | Threads, compaction, skills, memory features | Native sandbox + approval requests; broker custom effects | Medium–high binary/protocol/auth work | Optional coding worker |
| Codex TS SDK | Same underlying Codex engine | No equivalent app-server callback surface in fetched SDK | JSON exec events + abort; no public live steer method | Resume native threads | Configuration flags, not rich approval exchange | Low initial, high when escaping SDK limits | Batch coding only |
| OpenCode server / new embedded SDK | Multi-provider engine | Plugins, schemas, MCP | Server events; v2 inbox steering + interrupt | Engine database, compaction, skills | Runtime permission service; isolate privileged plugins | Medium–high; v1/v2 docs and dependency split | Serious comparator, pin generation |

## 4. Installed Vercel AI SDK 7: strongest incremental fit

**Contracts actually inspected**

- `ai/src/agent/tool-loop-agent.ts` exports `ToolLoopAgent`; `generate()` and `stream()` use the SDK's core execution functions. This is an in-process library, not a required hosted Vercel service. [Source](https://github.com/vercel/ai/blob/ede06e32cf5ac1d79e29bc07cd4e3839e8998a0b/packages/ai/src/agent/tool-loop-agent.ts).
- Default agent cap is 20 steps; choose explicit stop conditions, time/cost budgets, and tool concurrency for desktop actions. `prepareStep` can change model, active tools, messages, and context between steps. [Docs](https://ai-sdk.dev/docs/agents/loop-control), [settings](https://github.com/vercel/ai/blob/ede06e32cf5ac1d79e29bc07cd4e3839e8998a0b/packages/ai/src/agent/tool-loop-agent-settings.ts).
- Streaming is consumable without HTTP or React; stream results can be adapted to Electron IPC. Existing providers can be passed as model objects rather than Gateway model strings. [Loop source](https://github.com/vercel/ai/blob/ede06e32cf5ac1d79e29bc07cd4e3839e8998a0b/packages/ai/src/agent/tool-loop-agent.ts), [Workflow model examples](https://ai-sdk.dev/docs/agents/workflow-agent).
- Installed exports include `experimental_createSteering`; `experimental_steering` is accepted by `ToolLoopAgent`, not merely by raw model calls. Delivery occurs at a step boundary and returns an outcome. [Steering source](https://github.com/vercel/ai/blob/ede06e32cf5ac1d79e29bc07cd4e3839e8998a0b/packages/ai/src/generate-text/steering.ts), [loop control](https://ai-sdk.dev/docs/agents/loop-control).
- Steering does not mean immediate interruption of an executing effect. Use `abortSignal` for cooperative cancellation and a broker-side revocation check for queued/in-flight privileged actions. [Agent source](https://github.com/vercel/ai/blob/ede06e32cf5ac1d79e29bc07cd4e3839e8998a0b/packages/ai/src/agent/tool-loop-agent.ts), [steering docs](https://ai-sdk.dev/docs/agents/loop-control).
- Important persistence trap: steering is **not** included in `responseMessages`; reconstruct ordered history using per-step steering records, or journal user input independently. [Loop docs](https://ai-sdk.dev/docs/agents/loop-control).

**Approvals, tools, MCP**

- `toolApproval` can be a per-tool map or generic policy callback; statuses distinguish automatic approval, denial, user decision, and non-applicability. It takes precedence over tool-defined settings. [Contract](https://github.com/vercel/ai/blob/ede06e32cf5ac1d79e29bc07cd4e3839e8998a0b/packages/ai/src/generate-text/tool-approval-configuration.ts), [policy guide](https://ai-sdk.dev/docs/agents/policy-tool-approvals).
- `runtimeContext` and per-tool `toolsContext` are typed policy/execution context, not model-authored capabilities. Use opaque broker references rather than credentials or renderer-controlled authority. [Settings](https://github.com/vercel/ai/blob/ede06e32cf5ac1d79e29bc07cd4e3839e8998a0b/packages/ai/src/agent/tool-loop-agent-settings.ts), [approval contract](https://github.com/vercel/ai/blob/ede06e32cf5ac1d79e29bc07cd4e3839e8998a0b/packages/ai/src/generate-text/tool-approval-configuration.ts).
- `experimental_toolApprovalSecret` signs requests and validates replayed approval data; this does not supply expiration, capability revocation, or a durable once-only effect ledger. Those remain HeyNimbo requirements. [Setting](https://github.com/vercel/ai/blob/ede06e32cf5ac1d79e29bc07cd4e3839e8998a0b/packages/ai/src/agent/tool-loop-agent-settings.ts), [signature implementation](https://github.com/vercel/ai/blob/ede06e32cf5ac1d79e29bc07cd4e3839e8998a0b/packages/ai/src/generate-text/tool-approval-signature.ts).
- Custom tools use SDK schemas plus host execution; async tool results can expose progress. MCP is the separate `@ai-sdk/mcp` client package, not an installed `ai` export. [MCP guide](https://ai-sdk.dev/docs/ai-sdk-core/mcp-tools), [package](https://github.com/vercel/ai/blob/ede06e32cf5ac1d79e29bc07cd4e3839e8998a0b/packages/mcp/package.json).
- MCP definitions, servers, and their downstream integrations still need broker policy; an MCP tool is not intrinsically read-only or isolated. **Design conclusion** from the executable-tool contract and the separate approval mechanism above.

**History, memory, skills, delegation, testing**

- `ToolLoopAgent` is not a persistent agent database. The memory guide offers provider tools, external services, or custom storage-backed tools; provider-neutral local SQLite memory is an application implementation. [Memory](https://ai-sdk.dev/docs/agents/memory), [Workflow durability distinction](https://ai-sdk.dev/docs/agents/workflow-agent).
- Subagents are documented composition through tools calling another agent; cancellation must be explicitly forwarded. This is not a ready-made durable desktop task scheduler. [Subagents](https://ai-sdk.dev/docs/agents/subagents).
- `uploadSkill` is an installed export, but no general learned-skill lifecycle or universal memory service is exported by `ai`; build host-owned SKILL.md indexing, provenance, review, and injection rather than confusing upload helpers with learning. [Installed export evidence](evidence/harness-ai-probe-result.json), [memory options](https://ai-sdk.dev/docs/agents/memory).
- Installed `ai/test` exports V4 mock models. A real local no-network probe verified denial blocks execution, user-approval pauses with a request, both context channels arrive, steering reaches step 1, and streamed text is consumable. Evidence: `harness-ai-probe.mjs`, `harness-ai-probe-result.json`.
- **Cancellation counterexample:** with deliberately uncooperative mock provider/tool implementations, a pre-aborted call rejected with AbortError but still invoked the unguarded mock effect once. Checking the received signal inside the host tool reduced effect invocations to zero. This is a deterministic boundary probe, not a claim all real providers behave this way. Evidence: `harness-ai-probe-result.json`.
- Therefore provider cancellation and UI cancellation are insufficient authorization checks; privileged execution must independently validate cancellation/revocation at its own boundary. **Conclusion from the local probe**, not a claimed universal SDK guarantee.
- Source tests include steering and approval-signature tampering cases; they were fetched/read, not run as an upstream full suite. [Steering tests](https://github.com/vercel/ai/blob/ede06e32cf5ac1d79e29bc07cd4e3839e8998a0b/packages/ai/src/agent/tool-loop-agent-steering.test.ts), [signature tests](https://github.com/vercel/ai/blob/ede06e32cf5ac1d79e29bc07cd4e3839e8998a0b/packages/ai/src/generate-text/tool-approval-signature.test.ts).

**WorkflowAgent is not already-installed durability**

- It is imported from **`@ai-sdk/workflow`**, requiring **`workflow@5`**, `ai`, and `zod`; neither class nor workflow engine is supplied by installing `ai` alone. [Current guide](https://ai-sdk.dev/docs/agents/workflow-agent), [package](https://github.com/vercel/ai/blob/ede06e32cf5ac1d79e29bc07cd4e3839e8998a0b/packages/workflow/package.json).
- Its persistence and approvals run through Workflow DevKit steps, directives, runtime streams, and resume semantics. A native Electron host needs a supported workflow runtime/build/deployment story before adopting it; this investigation did not prove that integration. [Guide](https://ai-sdk.dev/docs/agents/workflow-agent).
- Therefore use SQLite checkpoints around our owned substrate first; fall back to a manually checkpointed `streamText` loop where automatic execution cannot meet persistence boundaries. **Recommendation**, not a claim that either strategy magically guarantees exactly-once actions.

## 5. Hermes: substantial reusable runtime, real Python cost

- Started with the official live [llms.txt](https://hermes-agent.nousresearch.com/docs/llms.txt), then fetched current integration, library, security, memory, skills, and middleware documentation plus pinned implementation.
- `run_agent.py::AIAgent` composes loop and lifecycle helpers; initialization exposes streaming deltas, tool progress/start/completion, reasoning, and event callbacks. [Core](https://github.com/NousResearch/hermes-agent/blob/fcc26fbd9f1641755e49793d7ed608f3b7214c3d/run_agent.py), [loop](https://github.com/NousResearch/hermes-agent/blob/fcc26fbd9f1641755e49793d7ed608f3b7214c3d/agent/conversation_loop.py).
- Library entrypoints include `chat()` and `run_conversation()` with supplied history; quiet embedding is supported. A fresh instance per concurrent task is advised, not one mutable global agent. [Library](https://github.com/NousResearch/hermes-agent/blob/fcc26fbd9f1641755e49793d7ed608f3b7214c3d/website/docs/guides/python-library.md).
- Do not invent a JS Hermes SDK or `--mode rpc`: supported integrations are ACP, TUI-gateway JSON-RPC, and HTTP/SSE API surfaces. [Integration](https://github.com/NousResearch/hermes-agent/blob/fcc26fbd9f1641755e49793d7ed608f3b7214c3d/website/docs/developer-guide/programmatic-integration.md).
- TUI gateway exposes `prompt.submit`, `session.steer`, `session.interrupt`, history, branching, compaction, model switching, and subagent controls. It is a useful desktop-host protocol, not just terminal scraping. [Integration](https://github.com/NousResearch/hermes-agent/blob/fcc26fbd9f1641755e49793d7ed608f3b7214c3d/website/docs/developer-guide/programmatic-integration.md).
- Server-to-client approvals/questions are JSON-RPC **requests**, not ordinary stream events; advertise `client.capabilities` server-request support and answer matching IDs. Reconnection can replay still-open requests. [Integration](https://github.com/NousResearch/hermes-agent/blob/fcc26fbd9f1641755e49793d7ed608f3b7214c3d/website/docs/developer-guide/programmatic-integration.md).
- HTTP has `/v1/runs`, event streams, steer, stop, and approval resolution; steering acceptance means queued input, and undelivered guidance may return in terminal status. Feature-detect capabilities rather than assume Chat Completions exposes the full agent contract. [Integration](https://github.com/NousResearch/hermes-agent/blob/fcc26fbd9f1641755e49793d7ed608f3b7214c3d/website/docs/developer-guide/programmatic-integration.md).
- ACP supports session prompts, cancellation, tool events, and permission bridging; exact permission handling lives in `acp_adapter/permissions.py`. [Server](https://github.com/NousResearch/hermes-agent/blob/fcc26fbd9f1641755e49793d7ed608f3b7214c3d/acp_adapter/server.py), [permissions](https://github.com/NousResearch/hermes-agent/blob/fcc26fbd9f1641755e49793d7ed608f3b7214c3d/acp_adapter/permissions.py).
- Custom tools register schemas/handlers in `tools/registry.py`; desktop functionality can be bridged by a Python plugin or MCP rather than rewriting Rust or Electron in Python. [Registry](https://github.com/NousResearch/hermes-agent/blob/fcc26fbd9f1641755e49793d7ed608f3b7214c3d/tools/registry.py), [MCP registration](https://github.com/NousResearch/hermes-agent/blob/fcc26fbd9f1641755e49793d7ed608f3b7214c3d/tools/mcp_tool_registration.py).
- The execution path has tool guardrails and dispatch helpers; enforcing every privileged effect still requires controlling what tool handlers and terminal backends can reach. [Executor](https://github.com/NousResearch/hermes-agent/blob/fcc26fbd9f1641755e49793d7ed608f3b7214c3d/agent/tool_executor.py), [guardrails](https://github.com/NousResearch/hermes-agent/blob/fcc26fbd9f1641755e49793d7ed608f3b7214c3d/agent/tool_guardrails.py).
- **Critical security limitation:** middleware failures are documented as fail-open. A middleware-only permission implementation that throws on broker failure is not a fail-closed boundary. Put enforcement in the privileged host tool and OS containment. [Middleware](https://github.com/NousResearch/hermes-agent/blob/fcc26fbd9f1641755e49793d7ed608f3b7214c3d/website/docs/developer-guide/middleware.md).
- Dangerous-command approvals are not comprehensive effect classification; current security docs explicitly distinguish file-write guards, optional safe roots, command patterns, container behavior, and executable Python. Do not summarize Hermes as prompting for every write. [Security](https://github.com/NousResearch/hermes-agent/blob/fcc26fbd9f1641755e49793d7ed608f3b7214c3d/website/docs/user-guide/security.md), [approval implementation](https://github.com/NousResearch/hermes-agent/blob/fcc26fbd9f1641755e49793d7ed608f3b7214c3d/tools/approval.py).
- Broad direct/native/local provider routing is a first-class runtime concern; changing engines would still add another provider/config/auth ownership layer alongside current AI SDK adapters. [Provider runtime](https://hermes-agent.nousresearch.com/docs/developer-guide/provider-runtime).
- Persistent local memory includes MEMORY.md/USER.md and searchable sessions; model-visible snapshots and memory management are deliberate rather than merely unbounded transcript replay. [Memory](https://github.com/NousResearch/hermes-agent/blob/fcc26fbd9f1641755e49793d7ed608f3b7214c3d/website/docs/user-guide/features/memory.md), [manager](https://github.com/NousResearch/hermes-agent/blob/fcc26fbd9f1641755e49793d7ed608f3b7214c3d/agent/memory_manager.py).
- Skills are editable reusable documents with discovery/management and progressive exposure; this is the strongest built-in learning-story match among these candidates. **Comparative judgment** based on [skills docs](https://github.com/NousResearch/hermes-agent/blob/fcc26fbd9f1641755e49793d7ed608f3b7214c3d/website/docs/user-guide/features/skills.md).
- Context compression is a substantial reusable subsystem, not a small summarizer utility to copy unexamined. [Compressor](https://github.com/NousResearch/hermes-agent/blob/fcc26fbd9f1641755e49793d7ed608f3b7214c3d/agent/context_compressor.py).
- Testing evidence includes ACP permission tests and an extensive interrupt-oriented tree; source tests were inspected, not executed in this task. [Permission tests](https://github.com/NousResearch/hermes-agent/blob/fcc26fbd9f1641755e49793d7ed608f3b7214c3d/tests/acp_adapter/test_permissions.py), [retrieved tree](https://api.github.com/repos/NousResearch/hermes-agent/git/trees/fcc26fbd9f1641755e49793d7ed608f3b7214c3d?recursive=1).
- Packaging requires Python `>=3.11,<3.15` at this revision, dependency selection, and Hermes' environment-management lifecycle. No supported wheel/sdist path is promised by current library docs. [Manifest](https://github.com/NousResearch/hermes-agent/blob/fcc26fbd9f1641755e49793d7ed608f3b7214c3d/pyproject.toml), [library](https://github.com/NousResearch/hermes-agent/blob/fcc26fbd9f1641755e49793d7ed608f3b7214c3d/website/docs/guides/python-library.md).
- For a distributable Mac app, budget interpreter distribution, signed executables/native wheels, process startup/shutdown, updates, profile isolation, and RPC version tests. **Engineering-cost assessment**, not evidence that an existing bundler already solves these.
- Verdict: Hermes is a viable optional local or self-hosted **generalist sidecar**, especially for memory/skills; adopting it as core would duplicate session/provider ownership and add Python packaging instead of reducing the hardest desktop work.

## 6. Codex: app-server and TypeScript SDK are not interchangeable

**App-server**

- The official interface is a bidirectional protocol for rich clients, with initialization, thread lifecycle, turns, items, requests, and notifications. Use stdio for a local child rather than an unnecessary listening server. [Official docs](https://developers.openai.com/codex/app-server/).
- Core flow: initialize, start/resume/fork thread, start turn, consume item/turn notifications. History belongs to native Codex threads; do not treat an SDK UI transcript as its authoritative store. [Official docs](https://developers.openai.com/codex/app-server/), [thread contract](https://github.com/openai/codex/blob/2681f8cba2831ef72bca2c0672b2e49d5f690745/codex-rs/app-server-protocol/src/protocol/v2/thread.rs).
- `turn/steer` requires the expected active turn ID; `turn/interrupt` targets thread and turn IDs. These are real protocol capabilities, not simulated follow-up prompts. [Turn contract](https://github.com/openai/codex/blob/2681f8cba2831ef72bca2c0672b2e49d5f690745/codex-rs/app-server-protocol/src/protocol/v2/turn.rs), [steer tests](https://github.com/openai/codex/blob/2681f8cba2831ef72bca2c0672b2e49d5f690745/codex-rs/app-server/tests/suite/v2/turn_steer.rs).
- Desktop custom tools can use experimental `dynamicTools` and client-executed `item/tool/call`; advertise experimental support, validate schemas, and route every effect through the broker. [Docs](https://developers.openai.com/codex/app-server/), [dynamic handler](https://github.com/openai/codex/blob/2681f8cba2831ef72bca2c0672b2e49d5f690745/codex-rs/core/src/tools/handlers/dynamic.rs).
- Native execution approvals and filesystem-change approval requests must remain distinct from HeyNimbo approvals for screenshots, AX typing, sending, or spending. OS sandbox permissions cannot authorize our external MCP/desktop service. [Native permission contract](https://github.com/openai/codex/blob/2681f8cba2831ef72bca2c0672b2e49d5f690745/codex-rs/app-server-protocol/src/protocol/v2/permissions.rs).
- Providers are configurable, including local OSS endpoints, but the fetched `WireApi` contract is Responses-oriented and explicitly rejects the removed chat wire mode. This is **not** a drop-in replacement for every installed AI SDK adapter. [Provider source](https://github.com/openai/codex/blob/2681f8cba2831ef72bca2c0672b2e49d5f690745/codex-rs/model-provider-info/src/lib.rs).
- Do not claim Codex is strictly OpenAI-only; do not claim equivalent Anthropic/Gemini/local compatibility either. Validate exact model, tool, image, reasoning, and endpoint behavior under the pinned binary. [Provider source](https://github.com/openai/codex/blob/2681f8cba2831ef72bca2c0672b2e49d5f690745/codex-rs/model-provider-info/src/lib.rs).
- MCP integration, skill input, compaction, and thread-memory facilities exist; persistent HeyNimbo profile memory should remain engine-independent rather than being conflated with Codex's coding-oriented state. ## 10. Owned substrate and enforcement design

The following is **proposed HeyNimbo design**, not an API any candidate already supplies:

1. Electron main owns run admission and durable SQLite records; use an isolated utility/worker process for the model loop, not renderer authority.
2. Canonical entities: conversation, run, ordered event, turn checkpoint, tool intent, approval, effect receipt, capability grant, memory entry, skill revision.
3. Every privileged call resolves a host-owned capability scoped by session, resource, operation, expiry, budget, and cancellation generation.
4. Validate and normalize parameters before asking; bind the exact approved arguments/resource to the eventual effect and re-check immediately before execution.
5. Do not expose raw credentials or a broker bypass through shell, Python, plugins, MCP servers, or delegated workspaces.
6. Cancellation revokes capabilities first, then requests cooperative abort, then escalates process termination if needed; already-committed remote effects cannot be undone by aborting tokens.
7. Journal intent before a side effect and receipt afterward; classify uncertain restart outcomes as unknown. Never blindly replay sends, purchases, GUI clicks, or unsafely repeatable shell commands.
8. A coding sidecar receives a bounded workspace, reduced environment, no desktop credentials, and a broker-controlled MCP/dynamic-tool channel. Host filesystem/egress restrictions must be actual containment, not a prompt.
9. Native engine sandbox requests and HeyNimbo action approvals are separate policy inputs; aggregate effective authority restrictively, never translate one approval into blanket trust.
10. The common event envelope retains native engine IDs, raw diagnostic payload references, approval requests/responses, tool intent/effect status, and ordering; text-only normalization is insufficient.
11. Host memory is engine-neutral: SQLite/FTS, explicit provenance, scoped retrieval, editable/deletable records. Learned skills are versioned inert documents with review and revocation, not silently trusted executable plugins.
12. Speech-paced scene events remain declarative and validated; separate model progress from audio playback, capture sessions, and renderer lifetimes.

### Practical composition sequence

- **Choose now:** installed AI SDK thin loop plus owned substrate; no new runtime dependency is needed to prove typed tools, denial, streaming, or steering.
- Start `ToolLoopAgent` with explicit budgets and broker-wrapped execution; persist turns and ordered user steering independently of SDK return objects.
- If its automatic steps cannot checkpoint tool intents before execution or satisfy restart recovery, use single-step/manual `streamText` orchestration while retaining provider/tool schemas.
- Add one optional coding adapter, not four: direct pinned Codex app-server if native approvals matter; Pi if provider breadth and all-TypeScript embedding outweigh adapter migration.
- Keep Hermes as opt-in managed sidecar until Python distribution and host-memory ownership are intentional product decisions.
- Treat new OpenCode SDK and AI HarnessAgent as focused compatibility spikes before committing; neither has been integrated or tested inside this Electron app in this task.

### Where adoption saves work, and where it does not

These are proposed allocation boundaries and integration-cost judgments, not candidate feature guarantees.

| Work item | Thin AI composition | Adopt a full engine |
|---|---|---|
| Provider calls and tool JSON validation | Reuse existing adapters and schemas | Map or replace existing provider/message contracts |
| Turn scheduling and budgets | Explicit host policy around loop steps | Reconcile host policy with native scheduler |
| Desktop tools and permissions | Broker wrappers are the only privileged path | Bridge broker plus remove/isolate native bypass paths |
| Conversation identity | One host-owned identity and journal | Map host IDs to native thread/session IDs |
| Recovery after unknown side effects | Host intent/receipt rules | Same rules plus native recovery semantics |
| Long-term user memory | Implement local scoped retrieval and editing | Decide whether to migrate, mirror, or subordinate native memory |
| Learned skills | Host-managed versioned documents | Reconcile native discovery, mutation, and trust policy |
| Streaming UI and voice/scene timing | App protocol remains authoritative | Translate native events without surrendering playback ownership |
| Installation and updates | Existing JS/runtime distribution | Additional package/binary/service lifecycle and compatibility pins |

The full-engine path saves coding-harness behavior, compaction, native history, and sometimes memory/skills implementation.
It does not remove the desktop capability broker, model-quality validation, trusted UI, recovery policy, or external-action correctness work.
A thin composition is preferable here because those unsolved desktop responsibilities are the product's differentiator, while provider plumbing is already present.

## 11. Acceptance tests before any engine is trusted

- Contract: start/resume/fork, ordered text/tool events, missing/late approvals, reconnect/replay, steer delivered versus merely queued, and interrupt terminal states.
- Security: denied custom call never executes; stale approval cannot authorize changed arguments; broker outage denies; delegated shell/plugin cannot reach desktop secrets or bypass MCP controls.
- Cancellation: abort during provider stream, tool wait, approval prompt, subprocess, nested delegation, and GUI actuation; verify revoked generations prevent delayed calls.
- Recovery: crash between tool intent/effect/receipt, duplicate response delivery, stale thread IDs, missing native sessions, dropped volatile events, and unknown external-write outcomes.
- Providers: one direct native provider, OpenAI-compatible/local endpoint, images, tool errors, reasoning/context limits, and model switches; never infer parity from a provider selector.
- Product invariants: screenshot consent scope, speech-clock continuity, scene cancellation, multiple displays, profile isolation, disk retention, and no prompt-visible secrets.
- Packaging: clean macOS install without developer Python/Bun/toolchains, signed binaries/native modules, offline startup, engine pin mismatch, and safe update rollback.
